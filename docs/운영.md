# 운영

서버를 계속 띄워 두고 쓰는 사람을 위한 이야기입니다.
혼자 세션 때만 켜서 쓰는 경우에는 읽지 않아도 됩니다.

## 암호 두 가지

| 암호 | 누가 씁니까 |
|---|---|
| **입장 암호** | 플레이어가 방에 들어올 때 |
| **GM 암호** | 서브 GM이 GM으로 들어올 때 |

둘 다 비워둘 수 있습니다. 링크를 알아도 암호 없이는 못 들어옵니다. 두 암호 모두 GM 대시보드 왼쪽 위에 항상 보이고 세션 중에 바꿀 수 있습니다. 틀린 입장 암호를 8번 넣으면 그 IP는 1분간 막힙니다.

> 암호는 해시가 아니라 원문으로 저장됩니다 (GM이 다시 확인해서 알려줘야 하는 값이라서). **개인 계정 비밀번호를 재사용하지 마세요** — 이 방에만 쓰는 단어를 정하세요.

## 📁 기본 알림음·표시 넣어두기

서버의 아래 폴더에 파일을 넣어 두면 **이 서버를 쓰는 모두에게** 기본으로 보입니다.
(NAS에서는 `/share/Container/podam/public/assets/` 아래입니다.)

| 폴더 | 쓰임 | 형식 |
|---|---|---|
| `public/assets/sounds/` | 알림음 · 타이머 종료음 | mp3, wav, ogg, m4a, aac, flac |
| `public/assets/emoji/` | 대화에 붙이는 표시 | png, gif, webp, jpg (48×48 권장) |

파일 이름이 그대로 목록에 나오므로 알아보기 쉬운 이름을 쓰세요.
넣거나 뺀 뒤 브라우저에서 **Ctrl+F5** 하면 반영됩니다 (컨테이너 재시작 불필요).
개인적으로 쓰는 소리는 여전히 「＋ 소리 파일 등록…」으로 자기 브라우저에만 넣을 수 있습니다.

## 서버에 올려 두기 (추천)

늘 켜 두는 서버(집 NAS·구석의 미니 PC·빌린 가상 서버)에 올려 두면 **내 PC를 켜 둘 필요가 없고**
주소도 계속 살아 있습니다. 도커만 돌면 어디든 됩니다.
설치 방법은 [서버에-올리기.md](서버에-올리기.md)에 있습니다. `docker-compose.yml` 을 그대로 쓰면 됩니다.

코드를 고친 뒤에는 `src/` 와 `public/` 만 서버로 보내면 됩니다 — `public/` 은 새로고침,
`src/` 는 컨테이너 재시작이면 반영됩니다 (이미지를 다시 만들지 않습니다).

포트포워딩은 하지 않습니다 — `cloudflared`가 바깥으로 나가는 연결만 쓰므로 NAS가 인터넷에 노출되지 않습니다.

## 클라우드 배포 (선택)

내 PC도 NAS도 없을 때. 터널 방식이 번거로워지면 그때 넘어가세요.

**볼륨을 반드시 붙이세요.** 무료 플랜의 휘발성 디스크에 올리면 재시작 때 DB와 업로드 파일이 사라집니다.

Railway / Fly.io:
1. 저장소 연결 (`Dockerfile` 자동 인식)
2. 볼륨 1GB를 `/data`에 마운트
3. 환경변수 `DATA_DIR=/data`

```bash
docker build -t podam .
docker run -p 3000:3000 -v mm-data:/data podam
```

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | |
| `DATA_DIR` | `./data` | SQLite와 업로드 파일 위치 |
| `MAX_UPLOAD_MB` | 50 | 파일 하나당 최대 크기 |
| `REQUIRE_CREATE_PASSWORD` | (안 적으면 암호 유무를 따름) | `true` 면 **방 만들기에 암호가 필요합니다.** `false` 면 주소를 아는 누구나 방을 만듭니다. `true` 인데 아래 암호가 비어 있으면 안전하게 방 만들기를 막습니다 |
| `CREATE_PASSWORD` | (없음) | 위가 `true` 일 때 쓸 암호. 인터넷에 열어두는 경우 반드시 설정하세요 |
| `PURGE_GRACE_DAYS` | 30 | 보관 기간이 끝나고 이 일수가 더 지나면 방·기록·파일을 자동 삭제합니다. `0`이면 자동 삭제를 끕니다 |
| `BACKUP_DIR` | (없음) | 정하면 그 폴더로 **기록과 자료를 자동 백업**합니다. 비우면 백업하지 않습니다 |
| `BACKUP_EVERY_HOURS` | 6 | 백업 주기 |
| `BACKUP_KEEP` | 7 | 보관할 스냅샷 개수 (오래된 것부터 정리) |
| `TRUST_PROXY` | (없음) | 프록시·터널 뒤에 둘 때 `1`. 원래 접속자 IP를 `X-Forwarded-For`에서 읽습니다 — 이게 없으면 암호 제한이 모든 플레이어를 한 사람으로 취급합니다. |

**보낼 수 있는 파일** (확장자로 판단합니다 — 브라우저가 붙이는 MIME은 믿을 수 없어서):

| 종류 | 확장자 |
|---|---|
| 문서 | pdf, txt, md, rtf, csv, doc(x), xls(x), ppt(x), **hwp/hwpx**, odt/ods/odp |
| 이미지 | png, jpg, gif, webp, bmp, heic, avif |
| 압축 | **zip**, 7z, rar, tar, gz |
| 소리 | mp3, wav, ogg, m4a, flac, aac |
| 영상 | mp4, webm, mov, mkv |

실행 파일(exe, bat, ps1, js, jar…)과 **html/svg는 막습니다.** 업로드 파일이 이 앱과 같은 출처에서 제공되므로, 브라우저에서 실행되는 문서를 허용하면 남의 세션을 훔치는 스크립트를 심을 수 있기 때문입니다. 같은 이유로 이미지·PDF·오디오·영상 외에는 전부 내려받기로만 열립니다.

## 💾 자동 백업

대화 기록(`mm.sqlite`)과 올린 자료는 도커 볼륨 안에 있어 File Station에서 손댈 수 없습니다.
`BACKUP_DIR` 을 정하면 **밖에서 열어볼 수 있는 폴더로 사본을 만들어 둡니다.**

```
<백업폴더>/db/mm-20260917-030000.sqlite   ← 시점별 스냅샷 (BACKUP_KEEP 개까지)
<백업폴더>/uploads/<저장이름>             ← 올린 자료 사본 (새 것만 복사)
```

- 서버가 켜진 뒤 1분, 그다음부터 `BACKUP_EVERY_HOURS` 마다 돕니다.
- sqlite는 **WAL 모드**라 파일을 그냥 복사하면 최신 대화가 빠집니다. sqlite 자체의 백업 기능을 써서
  일관된 스냅샷을 만들고, 다 쓴 뒤에 이름을 바꿉니다(쓰다 만 파일이 정상 사본으로 오인되지 않게).
- 자료 파일은 **이미 있는 것은 건너뛰고** 새 것만 복사합니다. NAS가 멎지 않도록 한 번에 하나씩 복사합니다.
- 정리(오래된 스냅샷 삭제)는 **새 스냅샷을 확보한 뒤에만** 합니다.
- 폴더가 없으면 만들고, 권한이 없거나 공간이 부족하면 **경고 한 줄만 남기고 서버는 그대로 돕니다.**
- `BACKUP_DIR` 을 데이터 폴더(`DATA_DIR`) 안으로 정하면 거부합니다 (백업이 백업을 복사하게 되므로).

**복구하려면** 컨테이너를 멈추고 스냅샷을 `mm.sqlite` 자리에 덮어쓴 뒤(같은 폴더의 `-wal`, `-shm` 파일은 지우고),
`uploads` 사본을 자료 폴더에 넣고 다시 시작하면 됩니다.

> NAS에서는 `docker-compose.yml` 의 볼륨 `- /share/Container/mm-backup:/backup` 과 `BACKUP_DIR: "/backup"` 이 짝입니다.
> 폴더를 미리 만들어 두고, **컨테이너가 uid 1000(node)으로 돌기 때문에** 그 계정이 쓸 수 있어야 합니다.

## 방 만들기 암호 켜고 끄기

`docker-compose.yml` 의 두 줄로 정합니다.

```
REQUIRE_CREATE_PASSWORD: "true"    # false 면 누구나 방을 만들 수 있다
CREATE_PASSWORD: "내가 정한 암호"
```

**환경변수는 컨테이너를 만들 때 한 번 박힙니다.** 파일만 고치거나 「다시 시작」을 해도 바뀌지 않으니,
Container Station에서 애플리케이션 → **다시 만들기(Recreate)** 를 누르면 나오는 YAML 편집기에서 고쳐야 합니다.
(「편집」은 CPU·메모리 설정만 보여줍니다.)

### YAML을 고치기 번거로울 때 — 파일로 설정하기

`src/settings.local.json` 을 만들어 두면 **환경변수보다 우선**합니다.
NAS 공유폴더(`/share/Container/podam/src/`)에서 바로 고칠 수 있고,
**몇 초 안에 반영되므로 컨테이너를 다시 시작할 필요도 없습니다.**

```json
{
  "REQUIRE_CREATE_PASSWORD": "true",
  "CREATE_PASSWORD": "내가 정한 암호",
  "PURGE_GRACE_DAYS": "7"
}
```

`src/settings.local.example.json` 을 복사해서 쓰면 됩니다.
이 파일은 `src/` 안에 있어 **웹으로는 공개되지 않고**(public 폴더가 아님), 저장소에도 올라가지 않습니다.

적용됐는지는 첫 화면에 **「서버 암호」 입력칸이 보이는지**로 확인합니다
(서버에 직접 물어보려면 `http://<주소>/api/config` 의 `needsCreatePassword` 값).

## 운영 메모

- 모르는 사람이 들어왔다면 **입장 잠금 + 내보내기**입니다 (위 「난입 막기」 참고).
- **「방 닫기」는 세션을 끝내는 게 아닙니다.** 플레이어의 입장·발송만 잠시 멈추고, GM은 그대로 쓸 수 있습니다. 「▶ 방 열기」로 언제든 되돌립니다. 잘못 눌러도 안전합니다.
- 정말 지우려면 **「방 삭제」** 입니다. GM 대시보드에서는 방 코드를 정확히 입력해야 실행되고, 랜딩 화면의 **내가 만든 방 목록**에서도 「방 삭제」로 지울 수 있습니다(확인 창). 대화 기록과 NAS에 저장된 파일까지 모두 지워지며 되돌릴 수 없습니다.
- 랜딩 화면의 **내가 만든 방 목록**에서 닫아둔 방도 「GM으로 열기」로 다시 들어가 열 수 있습니다.
- 방에는 보관 기간(기본 7일)이 있습니다. 지나면 새 플레이어는 입장할 수 없고(GM과 기존 플레이어는 계속 사용 가능), **그 뒤 30일이 더 지나면 자동으로 삭제**됩니다(`PURGE_GRACE_DAYS`). 서버는 시작할 때와 한 시간마다 확인합니다.
- 자료함에서 삭제해도 **이미 보낸 자료는 대화에 그대로 남습니다** (기록이 깨지지 않도록). 한 번도 안 보낸 파일만 디스크에서 지워집니다.
- 예약 발송은 없습니다. 진행 중 필요한 시점에 직접 보내는 편이 머더미스터리 진행에 맞다고 보고 뺐습니다.
