# 모듈 만들기

포담의 기능 중 **시나리오마다 달라지는 것**은 전부 모듈입니다. 정답 판정도, 간이 TRPG도,
AI 보조도 코어에 들어 있지 않고 폴더로 들어옵니다. 여러분이 만든 것도 똑같이 들어옵니다.

## 모듈은 폴더 하나입니다

```
<데이터폴더>/modules/
   내모듈/
     index.js          ← 이 파일 하나가 필수. 나머지는 마음대로
     schema.js         ← 표가 필요하면
     routes.js         ← GM 화면이 부를 API
     guide.js          ← 사용법 (앱 안 도움말에 그대로 붙는다)
     public/
       내모듈.gm.js     ← GM 화면
       내모듈.player.js ← 플레이어 화면
```

폴더를 넣고 포담을 다시 켜면 붙고, 빼면 없어집니다. 잠깐 꺼 두려면 **폴더 이름 앞에 `_`** 를
붙이세요(`_내모듈`). 데이터는 그대로 남습니다.

`<데이터폴더>` 가 어디인지는 켤 때 창에 찍힙니다. 아래는 윈도우에서의 한 예일 뿐,
드라이브가 정해져 있는 것은 아닙니다 (맥·리눅스는 각 운영체제의 자리를 씁니다).

```
모듈 3개: verdict, trpg, ai  (C:\Users\…\Podam\modules)
```

## 가장 작은 모듈

```js
'use strict';
const express = require('express');
const { db } = require('podam/db');
const { requireGm } = require('podam/guards');
const STATE = require('podam/modules/state');

const router = express.Router();
// 모든 라우트는 「GM인가」와 「이 방에서 이 모듈이 켜져 있는가」를 함께 본다.
const guard = [requireGm, (req, res, next) => (STATE.isEnabled(req.room, 'memo')
  ? next() : res.status(404).json({ error: '사용하지 않는 기능입니다' }))];

router.get('/gm/memo', guard, (req, res) =>
  res.json({ notes: db.prepare('SELECT * FROM memo_notes WHERE room_id = ?').all(req.room.id) }));

module.exports = {
  id: 'memo',
  name: '📝 쪽지',
  description: 'GM이 혼자 보는 쪽지를 방마다 둡니다.',
  api: 1,
  gmTab: { key: 'memo', label: '📝 쪽지' },
  schema: (d) => d.exec(`CREATE TABLE IF NOT EXISTS memo_notes (
    id TEXT PRIMARY KEY,
    room_id TEXT NOT NULL REFERENCES rooms(id) ON DELETE CASCADE,
    body TEXT NOT NULL)`),
  router,
  guide: { gm: '<p>GM 화면 오른쪽 📝 탭에 적습니다.</p>' },
};
```

**코어를 가져다 쓸 때는 `podam/…`** 입니다. `podam/db`·`podam/auth`·`podam/messages`·
`podam/guards`·`podam/upload`·`podam/modules/state` 가 `src/` 안의 같은 이름 파일입니다.
`express` 처럼 코어가 쓰는 라이브러리도 그대로 `require` 하면 됩니다 — 포담이 켜질 때 길을 놓아 줍니다.

## 디스크립터 — `index.js` 가 내놓는 것

| 필드 | 뜻 |
|---|---|
| `id` | 소문자·숫자·`-` 로 2~21자. **부팅 때 검사하고, 겹치면 서버가 안 뜹니다** |
| `name` · `description` | 모듈 고르는 화면에 보이는 글 |
| `api` | 이 모듈이 기대는 코어의 판. 지금은 `1`. 안 맞으면 안 실립니다 |
| `defaultOn` | 방을 만들 때 기본으로 켜 둘지 |
| `playerUi` | 플레이어에게 탭이 생기는가 (켜진 사실이 플레이어에게 알려집니다) |
| `playerGuide` | 탭은 없지만 플레이어가 사용법을 알아야 하는가 |
| `gmTab` | `{ key, label }` — GM 화면의 탭 |
| `attachTo` | 다른 모듈에 얹히는 확장이면 그 모듈 id (자기 탭을 만들지 않습니다) |
| `events` | 쓰는 소켓 이벤트 이름들. **반드시 `mod:<id>:` 로 시작**해야 하고 부팅 때 검사합니다 |
| `schema(db, addColumn)` | 표 만들기. 켤 때마다 불리므로 `IF NOT EXISTS` 로 |
| `router` | `/api` 아래에 붙습니다 |
| `socket({ io, socket, on })` | 소켓 이벤트 등록. `on` 은 이름 규칙과 모듈 on/off 를 알아서 봅니다 |
| `hooks` | 아래 참고 |
| `bundle` | 룸 셋팅에 담고 꺼내기 (`collect`/`apply`) |
| `guide` | `{ gm, player }` HTML. 앱 안 도움말에 그대로 들어갑니다 |
| `forget(roomId)` | 방이 사라질 때 메모리에 들고 있던 것 버리기 |

### 훅

| 훅 | 언제 |
|---|---|
| `playerSend(ctx)` | 플레이어 발화가 배달되기 **전**. 본문을 바꾸거나(`{ body }`) 가로챌 수 있습니다(`{ handled: true }`) |
| `afterPlayerSend(ctx)` | 배달된 뒤 |
| `fileAccess(ctx)` | 「이 파일을 이 사람이 열어도 되는가」. **기본은 거부**이고, 모듈이 `true` 라고 해야 열립니다 |
| `fileInUse(file)` | 「아직 쓰는 파일인가」. 자료함에서 지울 때 실물을 남길지 정합니다 |
| `socketAuth(auth)` | 사람이 아닌 **프로그램**이 붙는 길 (아래) |

훅은 **동기 함수**여야 하고, 터져도 대화는 그대로 배달됩니다. 다만 `fileAccess` 는 터지면 거부,
`fileInUse` 는 터지면 「쓰는 중」으로 봅니다 — 실수로 새거나 지워지는 쪽을 막는 방향입니다.

## 깨면 안 되는 것

이 프로그램의 바탕은 **사람마다 아는 것이 다르다**입니다. 모듈도 그 선을 지켜야 합니다.

1. **방 전체로 쏘는 길을 만들지 마세요.** `io.to('r:<방>')` 같은 것은 코어에도 없습니다.
   보낼 때는 `M.notifyGm` · `M.notifyParticipant` · `M.notifyEveryone` 만 씁니다.
2. **숨길 것은 목록에서 아예 빼세요.** 「보내고 화면에서 가리기」는 가린 게 아닙니다.
   역할별로 목록을 따로 만들어 각자에게 보냅니다.
3. **모르는 것을 아는 척하지 마세요.** 알 수 없는 상태는 비워 두는 편이 낫습니다.
4. **파일은 기본이 거부입니다.** `hooks.fileAccess` 로 열어 준 것만 열립니다.
5. **모듈이 꺼져 있으면 아무것도 되면 안 됩니다.** 라우트는 404, 소켓 이벤트는 거절.
   `on` 과 라우트 가드가 그 일을 해 줍니다.

## 화면 붙이기

`public/<id>.gm.js` / `public/<id>.player.js` 는 포담이 `/modules/<id>.gm.js` 로 내보냅니다.
안에서는 패널 하나를 등록합니다.

```js
MM.Panels.define({
  id: 'memo',
  side: 'gm',                  // 'gm' | 'player'
  label: '📝 쪽지',
  async mount(root, ctx) {
    const { notes } = await ctx.api('/api/gm/memo', { headers: ctx.AUTH() });
    root.innerHTML = notes.map((n) => `<p>${MM.esc(n.body)}</p>`).join('');
  },
});
```

`ctx` 로 오는 것: `api`·`socket`·`participants()`·`gms()`·GM 쪽은 `AUTH()`/`token()`,
플레이어 쪽은 `headers()`. 공용 도구는 `MM.esc`·`MM.toast`·`MM.makeDropzone`·`MM.makeSortable`·
`MM.copyAndTell` 등이 있습니다.

다른 모듈 위에 얹히는 확장이면 `attachTo: 'trpg'` 를 주고, 주인 모듈이 내주는 자리에 붙습니다.

## 검사

모듈도 검사가 있어야 합니다. `podam-modules` 저장소의 `test/harness.js` 를 그대로 가져다 쓰면
**코어를 끌어와 내 모듈만 얹은 서버**가 떠서, 거기에 대고 검사를 씁니다.

```js
const H = require('./harness');
const { check, section, api, connect, ask } = H;

(async function main() {
  await H.start();
  section(1, '쪽지 모듈');
  const room = await api('/api/rooms', {
    method: 'POST', body: { name: '시험', gmNickname: 'GM', modules: ['memo'] },
  });
  // …
  H.done();
})();
```

꼭 넣을 것 세 가지 — **모듈을 끈 방에서는 막히는가**, **플레이어 토큰으로는 못 하는가**,
**다른 방 사람에게 새지 않는가**.

## 나눠 주기

1. 저장소를 하나 만들고 폴더를 그대로 올립니다 (`modules/내모듈/…`).
2. Releases 에 **폴더를 압축한 zip** 하나를 올립니다.
3. 저장소에 토픽 **`podam-module`** 을 답니다 — 그게 지금의 「모듈 목록」입니다.

쓰는 사람은 zip 을 `<데이터폴더>/modules/` 에 풀고 다시 켜면 끝입니다.

> **받는 쪽에 알려 줄 것** — 모듈은 서버에서 도는 코드라 방·대화·파일에 모두 닿습니다.
> 읽을 수 있거나 믿는 모듈만 넣으라고 적어 두세요. 포담은 설치 화면을 따로 두지 않습니다.
> 주소를 넣어 받아오는 설치기를 만들면 「링크 하나로 남의 코드 실행」이 되기 때문입니다.

## 체크리스트

- [ ] `id` 가 짧고 겹치지 않는다
- [ ] `events` 가 전부 `mod:<id>:` 로 시작한다
- [ ] 모듈을 끄면 라우트도 소켓도 막힌다
- [ ] 플레이어에게 보내는 목록에 **숨겨야 할 것이 담기지 않는다**
- [ ] 파일을 쓴다면 `fileAccess` 로 열어 주고, `fileInUse` 로 지켜 준다
- [ ] 방을 지우면 내 표도 함께 사라진다 (`REFERENCES rooms(id) ON DELETE CASCADE`)
- [ ] `guide` 에 사용법을 적었다
- [ ] 룸 셋팅에 담을 것이 있으면 `bundle` 을 넣었다
- [ ] 검사가 있고, 끈 상태·권한·격리를 본다
- [ ] README 에 「무엇을 하는 모듈인지」 세 줄
