# 서버에 올리기 (도커)

**늘 켜 두는 서버**가 있으면 거기에 올려 두는 편이 편합니다. 세션 때마다 PC를 켜 둘 필요가 없고,
주소도 계속 살아 있습니다. 도커만 돌면 어디든 됩니다.

- 집에 있는 **NAS** (시놀로지·QNAP 등)
- 구석에 놓아둔 **미니 PC·노트북** (리눅스·윈도우)
- 빌려 쓰는 **가상 서버(VPS)**

아래 설명은 **QNAP Container Station 기준**입니다. 다른 환경이라면 경로와 화면 이름만 바꿔 읽으면 됩니다 —
하는 일은 어디서나 같습니다. `docker compose up -d` 한 줄로 끝나는 환경이라면 [docker-compose.yml](docker-compose.yml) 만 고쳐서 바로 올리셔도 됩니다.

**포트포워딩은 하지 않습니다.** `cloudflared` 가 서버에서 바깥으로 나가는 연결만 쓰기 때문에 공유기에 구멍을 뚫지 않아도 되고, 서버가 인터넷에 노출되지도 않습니다. 특히 NAS 는 인터넷에 직접 노출하면 랜섬웨어 표적이 되는 기기라(Deadbolt, Qlocker 등) 이 점이 중요합니다.

---

## 1. Container Station 설치

1. NAS 관리 화면(QTS) 접속 → **App Center**
2. 검색창에 `Container Station` → **설치**
3. 설치 후 실행 (처음 한 번 저장소 초기화를 물으면 그대로 진행)

> 안 보이거나 설치가 막히면 기종이 지원하지 않는 것입니다. 그 경우 알려주세요 — 다른 방법을 찾겠습니다.

## 2. 프로젝트 파일을 NAS에 올리기

프로젝트 폴더에서 **다음을 빼고** 전부 복사합니다.

- `node_modules/` (NAS에서 다시 설치됩니다)
- `data/` (내 PC의 기존 대화 기록)

File Station으로 NAS의 아무 공유폴더에 `podam` 폴더를 만들어 넣으면 됩니다.
예) `/share/Container/podam`

## 3. 애플리케이션 만들기

**Container Station → 애플리케이션 → 만들기**

- 이름: `podam`
- YAML 칸에 프로젝트의 **`docker-compose.yml` 내용을 그대로 붙여넣기**
- **만들기**

> **`failed to read dockerfile: no such file or directory` 가 뜬다면** 경로 문제입니다.
> Container Station은 YAML만 붙여넣으면 '작업 폴더'가 없어서 `./` 같은 상대 경로를 해석하지 못합니다.
> `docker-compose.yml` 안의 경로 세 곳이 **NAS의 실제 경로**인지 확인하세요.
>
> - 기본값은 `/share/Container/podam` 입니다 (Container 공유폴더에 둔 경우).
> - 그래도 안 되면 `/share/CACHEDEV1_DATA/Container/podam` 로 바꿔보세요.
> - 다른 공유폴더에 뒀다면 `/share/<공유폴더이름>/podam` 형태입니다.

첫 실행은 이미지를 받고 빌드하느라 **5~15분** 걸립니다 (`better-sqlite3`를 컴파일합니다). 두 번째부터는 빠릅니다.

> SSH를 쓰신다면 프로젝트 폴더에서 `docker compose up -d --build` 한 줄이면 됩니다.

## 4. 접속 주소 확인

**Container Station → 컨테이너 → `mm-tunnel` → 로그**

아래 같은 줄을 찾습니다.

```
|  https://무작위-단어-네개.trycloudflare.com  |
```

**이 주소로 접속해서 방을 만드세요.** 이게 플레이어에게 줄 주소입니다.

> NAS 주소(`http://192.168.x.x:8823`)로도 열리지만, **그걸로 방을 만들면 안 됩니다.** 플레이어 링크가 집 안 주소로 만들어져 바깥에서 안 열립니다. 그 상태로 접속하면 화면에 경고가 뜹니다.

## 보안

**NAS는 인터넷에 노출되지 않습니다.** `cloudflared`가 바깥으로 나가는 연결만 쓰기 때문에, QNAP 관리 화면·SMB·다른 앱은 밖에서 닿을 수 없습니다.

그 위에 다음을 걸어 뒀습니다.

| 항목 | 내용 |
|---|---|
| **서버 암호** | `CREATE_PASSWORD` — 이걸 모르면 **방을 만들 수 없습니다.** 주소가 새어도 남이 내 NAS에 파일을 쌓지 못합니다 |
| 생성 횟수 제한 | 같은 IP에서 1시간에 20개까지 |
| 실행 권한 | 컨테이너를 **root가 아닌 `node` 사용자**로 돌립니다 |
| 코드 보호 | `src`·`public` 을 **읽기 전용**으로 마운트해 컨테이너가 코드를 못 고칩니다 |
| 업로드 | 확장자 허용목록. `exe`·`bat`·`js`·`html`·`svg` 차단, 실행 가능한 문서는 다운로드로만 |
| 파일 저장 | 무작위 이름으로 저장해 경로 조작 불가 |

> **`docker-compose.yml` 의 `CREATE_PASSWORD` 를 반드시 바꾸세요.** 기본값이 그대로면 의미가 없습니다.

집 안에서 쓰는 `8823` 포트는 **같은 네트워크의 기기라면 누구나** 닿을 수 있습니다. 그것도 막고 싶으면 `ports:` 두 줄을 지우면 됩니다 (대신 현재 터널 주소를 로그에서 찾아야 합니다).

## 알아둘 것

**주소는 `mm-tunnel` 컨테이너를 다시 시작할 때만 바뀝니다.** NAS는 계속 켜져 있으니 몇 주씩 같은 주소를 씁니다. NAS를 재부팅하면 바뀌니 로그에서 다시 확인하세요.

**대화 기록과 파일**은 `mm-data` 볼륨에 쌓입니다. NAS 공유폴더에 두고 백업에 포함하고 싶으면 `docker-compose.yml`의 volumes를 이렇게 바꾸세요.

```yaml
    volumes:
      - /share/CACHEDEV1_DATA/podam-data:/data
```

**자동 백업**을 쓰려면 NAS에 백업 폴더를 먼저 만드세요 (예: `/share/Container/mm-backup`).
`docker-compose.yml` 의 `- /share/Container/mm-backup:/backup` 볼륨과 `BACKUP_DIR: "/backup"` 이 짝입니다.
컨테이너는 **uid 1000(node) 계정으로 돌기 때문에** 그 폴더에 쓸 수 있어야 합니다 —
권한이 없으면 서버는 그대로 돌고 로그에 `[백업] 실패 …` 한 줄만 남습니다.
백업된 파일은 File Station에서 그대로 열어볼 수 있습니다.

**파일 크기 한도**는 `MAX_UPLOAD_MB: "200"`으로 올려 뒀습니다. 더 필요하면 숫자만 바꾸고 다시 올리면 됩니다. 임시 주소(Cloudflare)를 쓰는 동안은 **요청 하나당 100MB**가 상한이니, 큰 파일은 하나씩 보내세요.

## 코드를 고친 뒤 반영하기

`src/` 와 `public/` 은 컨테이너 안에 복사하지 않고 **서버 폴더를 그대로 들여다보게** 해뒀습니다.
그래서 대부분의 수정은 **파일만 덮어쓰면 끝**이고, 이미지를 다시 만들 필요가 없습니다.

### 1단계 — 파일 보내기

고친 `src/` 와 `public/` 을 서버의 같은 자리에 덮어씁니다. 방법은 환경에 따라 아무거나 —

```bash
# 공유 폴더가 보이면 (NAS 등)
robocopy src  \\내서버\Container\podam\src  /E /XO
robocopy public \\내서버\Container\podam\public /E /XO

# ssh 가 되면
rsync -av --delete src public 사용자@내서버:/srv/podam/
```

NAS 라면 File Station 같은 파일 관리 화면으로 끌어다 놓아도 됩니다.
`data/` 와 `node_modules/` 는 건드리지 마세요 — 기록과 설치물이 거기 있습니다.

### 2단계 — 반영하기

무엇을 고쳤느냐에 따라 다릅니다.

| 고친 것 | 해야 할 일 | 걸리는 시간 |
|---|---|---|
| `public/` (화면·디자인) | **브라우저 새로고침** (Ctrl+F5) | 즉시 |
| `src/` (서버 로직) | Container Station → `podam` **다시 시작** | 몇 초 |
| `package.json` (라이브러리 추가) | 애플리케이션 **다시 만들기(Recreate)** | 5~15분 |

세션 중에 급히 화면 문구 하나 고치는 정도는 **새로고침만으로** 반영됩니다.

**대화 기록은 어느 경우에도 지워지지 않습니다.** 별도 볼륨에 있고, 스키마가 바뀌어도 기존 데이터를 유지한 채 컬럼만 추가됩니다.

> Container Station이 `./src` 같은 상대 경로를 못 찾는다고 하면, `docker-compose.yml` 의 그 두 줄을 NAS 실제 경로로 바꾸세요.
> 예) `- /share/Container/podam/src:/app/src:ro`

## 나중에 주소를 고정하려면

도메인을 하나 마련하면(연 1~2만원) 주소가 영원히 고정됩니다.

1. 도메인을 Cloudflare에 등록 (무료 플랜)
2. **Zero Trust → Networks → Tunnels → Create a tunnel** → 토큰 복사
3. 그 터널에 `mm.내도메인.com` → `http://app:3000` 연결 추가
4. `docker-compose.yml`의 tunnel 명령을 바꾸고 다시 올리기

```yaml
    command: tunnel --no-autoupdate run --token <복사한 토큰>
```

이러면 매번 로그에서 주소를 확인할 필요가 없고, 통신사 DNS가 새 주소를 못 찾는 문제도 함께 사라집니다.
